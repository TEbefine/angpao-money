## 4. ประวัติ (แท็บที่ 5)

ม้วน 3,000 รายการไม่ต้องวิ่งบนมือถืออีกแล้ว — `day_history()` รวมให้บน Postgres
ส่งกลับมาหน้าละ 14 วัน เลื่อนถึงท้ายจอโหลดต่อเอง (keyset ไม่ใช่ offset → หน้าที่ 20 เร็วเท่าหน้าแรก)

- แตะวันไหน = กางดูรายการของวันนั้น
- แถบสีใต้ยอด = สด / โอน / ยังไม่ระบุ
- เน็ตหลุด → คิดจากเครื่องแทน มีป้ายบอก ไม่มีจอว่าง

**วันตัดที่เที่ยงคืนกรุงเทพฯ** ไม่ใช่ UTC — เก็บเป็นคอลัมน์ `sale_day` ตอน insert
เพราะ `AT TIME ZONE` เป็นแค่ STABLE เลย index ตรง ๆ ไม่ได้

## 5. ซื้อของ

เดิมลิสต์อยู่ในตัวแปรเปล่า ๆ refresh ทีเดียวหายหมด — ตอนนี้:

- เก็บลง `S.buyDraft` → refresh แล้วยังอยู่
- ซิงก์ขึ้น `shopping_list` → ติ๊กที่เครื่องนี้ อีกเครื่องที่แม็คโครเห็นด้วย
- ชนกันแก้ด้วย last-writer-wins ต่อบรรทัด (เทียบ `updated_at` กับ `t` ในเครื่อง)
- กด "บันทึก" = กลายเป็นบิลซื้อ แล้วปิดแถวในลิสต์ (`done_purchase_id`)
- อยู่แท็บซื้อของจะดึงลิสต์ใหม่ทุก 15 วิ และตอนสลับกลับมาที่แอป

## หลักที่ยึดในโค้ด

- **append-only** — ลบ = insert แถว `void_of` ทับ ของเดิมไม่หาย เปลี่ยนวิธีจ่าย = insert `pay_changes`
- **price snapshot** — ราคาถูกถ่ายไว้ตอนขาย แก้ราคาวันนี้ไม่กระทบเมื่อวาน
- **optimistic update** — กดแล้วเลขขึ้นทันที ไม่รอ server
- **outbox** — ที่ยังส่งไม่ขึ้นคิวไว้ ต่อเน็ตแล้วส่งเอง
- **idempotent** — id สร้างฝั่ง client ส่งซ้ำก็ไม่เกิดรายการซ้ำ
- **local-first** — เปิดมาวาดจอจากเครื่องก่อน แล้วค่อยเช็ค server เบื้องหลัง
- **incremental pull** — ดึงเฉพาะที่เปลี่ยนหลัง `S.pulledAt` ไม่ใช่ `select=*` ทั้งกอง
- **เครื่องเป็นเจ้าของแคตตาล็อก** — server แค่ mirror เครื่องแรกที่ซิงก์ push ขึ้นไป
  ตอน pull ใช้ merge ไม่ใช่ replace ของเก่าที่ขายไปแล้วเลยไม่หลุด reference
